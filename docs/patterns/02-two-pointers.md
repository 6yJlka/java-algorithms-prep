# Two Pointers

Two Pointers — алгоритмический паттерн, при котором для обработки массива, строки
или связного списка используются два указателя.

Указатели могут:

- двигаться навстречу друг другу
- двигаться в одном направлении
- двигаться с разной скоростью
- ограничивать текущий диапазон элементов

Паттерн часто позволяет отказаться от вложенных циклов и уменьшить временную
сложность с `O(n²)` до `O(n)`.

## Основная идея

Вместо того чтобы проверять все возможные пары элементов, алгоритм использует
свойства входных данных и сдвигает только один или оба указателя.

Пример для строки:

```text
left → [ a, b, c, b, a ] ← right
```

После сравнения крайних символов указатели двигаются к центру:

```text
        left → [ b, c, b ] ← right
```

Каждый элемент обрабатывается ограниченное количество раз, поэтому полный проход
обычно занимает `O(n)`.

---

# Основные варианты Two Pointers

## 1. Указатели движутся навстречу

Один указатель находится в начале структуры, второй — в конце.

```java
int left = 0;
int right = values.length - 1;

while (left < right) {
    // обработка values[left] и values[right]

    left++;
    right--;
}
```

Этот вариант применяется, когда необходимо:

- сравнивать симметричные элементы
- найти пару в отсортированном массиве
- развернуть массив или строку
- проверить палиндром
- решить задачу `3Sum`
- уменьшать рассматриваемый диапазон

## Пример проверки палиндрома

```java
public static boolean isPalindrome(String value) {
    int left = 0;
    int right = value.length() - 1;

    while (left < right) {
        if (value.charAt(left) != value.charAt(right)) {
            return false;
        }

        left++;
        right--;
    }

    return true;
}
```

Примеры:

```java
isPalindrome("level"); // true
isPalindrome("abba");  // true
isPalindrome("java");  // false
isPalindrome("a");     // true
isPalindrome("");      // true
```

Сложность:

- время: `O(n)`
- дополнительная память: `O(1)`

Пустая строка считается палиндромом. Цикл для неё не выполняется, после чего
метод возвращает `true`.

---

## 2. Указатели движутся в одном направлении

Оба указателя начинают движение с начала структуры.

Обычно один указатель отвечает за чтение элементов, а второй — за позицию записи.

```java
int slow = 0;

for (int fast = 0; fast < values.length; fast++) {
    if (условие) {
        values[slow] = values[fast];
        slow++;
    }
}
```

Такой вариант часто называется `slow and fast pointers`.

Применяется для:

- удаления дубликатов
- фильтрации элементов на месте
- перемещения элементов
- сжатия массива
- формирования нового логического диапазона внутри исходного массива

## Пример удаления элементов

Пусть нужно оставить в массиве только положительные значения:

```java
public static int removeNonPositive(int[] values) {
    int slow = 0;

    for (int fast = 0; fast < values.length; fast++) {
        if (values[fast] > 0) {
            values[slow] = values[fast];
            slow++;
        }
    }

    return slow;
}
```

После выполнения первые `slow` элементов массива содержат положительные значения.

Пример:

```text
До:
[-2, 4, 0, 7, -1, 3]

После:
[4, 7, 3, ...]
```

Метод возвращает новую логическую длину массива.

Сложность:

- время: `O(n)`
- дополнительная память: `O(1)`

---

## 3. Указатели движутся с разной скоростью

Один указатель движется медленно, второй — быстрее.

Чаще всего:

- `slow` делает один шаг
- `fast` делает два шага

```java
ListNode slow = head;
ListNode fast = head;

while (fast != null && fast.next != null) {
    slow = slow.next;
    fast = fast.next.next;
}
```

Применяется для:

- поиска середины связного списка
- обнаружения цикла
- поиска точки входа в цикл
- определения длины цикла

## Почему slow окажется в середине

Пока `slow` проходит половину списка, `fast` проходит весь список.

Если длина списка равна `n`, то:

```text
slow проходит примерно n / 2 элементов
fast проходит примерно n элементов
```

Поэтому в момент завершения цикла `slow` находится около середины.

# Two Pointers для отсортированного массива

Один из самых распространённых сценариев — поиск пары в отсортированном массиве.

Пусть массив отсортирован по возрастанию:

```text
[1, 2, 4, 6, 10]
```

Нужно найти два числа, сумма которых равна `8`.

Ставим указатели:

```text
left                    right
 ↓                        ↓
[1, 2, 4, 6, 10]
```

Сумма:

```text
1 + 10 = 11
```

Она больше `8`, поэтому уменьшаем правый указатель:

```text
left                right
 ↓                    ↓
[1, 2, 4, 6, 10]
```

Теперь:

```text
1 + 6 = 7
```

Сумма меньше `8`, поэтому увеличиваем левый указатель:

```text
    left            right
      ↓               ↓
[1, 2, 4, 6, 10]
```

Получаем:

```text
2 + 6 = 8
```

Пара найдена.

## Шаблон поиска суммы

```java
public static boolean hasPairWithSum(int[] values, int target) {
    int left = 0;
    int right = values.length - 1;

    while (left < right) {
        int sum = values[left] + values[right];

        if (sum == target) {
            return true;
        }

        if (sum < target) {
            left++;
        } else {
            right--;
        }
    }

    return false;
}
```

Сложность:

- время: `O(n)`
- дополнительная память: `O(1)`

## Почему указатели можно двигать именно так

Массив отсортирован.

Если сумма слишком маленькая:

```text
values[left] + values[right] < target
```

уменьшать `right` бессмысленно, потому что сумма станет ещё меньше.

Нужно увеличить `left`, чтобы взять большее значение.

Если сумма слишком большая:

```text
values[left] + values[right] > target
```

увеличивать `left` бессмысленно, потому что сумма станет ещё больше.

Нужно уменьшить `right`.

Именно сортировка позволяет исключать целые группы неподходящих вариантов.

# Valid Palindrome

В задаче LeetCode 125 строка считается палиндромом, если после удаления
небуквенных и нецифровых символов она одинаково читается слева направо и справа
налево.

Регистр символов не учитывается.

Пример:

```text
"A man, a plan, a canal: Panama"
```

После очистки:

```text
amanaplanacanalpanama
```

## Решение через дополнительную строку

```java
public boolean isPalindrome(String s) {
    StringBuilder cleaned = new StringBuilder();

    for (int i = 0; i < s.length(); i++) {
        char currentCharacter = s.charAt(i);

        if (Character.isLetterOrDigit(currentCharacter)) {
            cleaned.append(
                    Character.toLowerCase(currentCharacter)
            );
        }
    }

    int left = 0;
    int right = cleaned.length() - 1;

    while (left < right) {
        if (cleaned.charAt(left) != cleaned.charAt(right)) {
            return false;
        }

        left++;
        right--;
    }

    return true;
}
```

Сложность:

- время: `O(n)`
- дополнительная память: `O(n)`

Память требуется для хранения очищенной строки.

## Оптимальное решение без дополнительной строки

```java
public boolean isPalindrome(String s) {
    int left = 0;
    int right = s.length() - 1;

    while (left < right) {
        while (
                left < right
                        && !Character.isLetterOrDigit(s.charAt(left))
        ) {
            left++;
        }

        while (
                left < right
                        && !Character.isLetterOrDigit(s.charAt(right))
        ) {
            right--;
        }

        char leftCharacter =
                Character.toLowerCase(s.charAt(left));

        char rightCharacter =
                Character.toLowerCase(s.charAt(right));

        if (leftCharacter != rightCharacter) {
            return false;
        }

        left++;
        right--;
    }

    return true;
}
```

Сложность:

- время: `O(n)`
- дополнительная память: `O(1)`

## Почему вложенные while не дают O(n²)

Внутренние циклы не начинают обход строки заново.

Левый указатель может переместиться от `0` до `n - 1` только один раз.

Правый указатель может переместиться от `n - 1` до `0` только один раз.

Общее количество перемещений указателей не превышает `O(n)`.

# Инвариант

Инвариант — условие, которое остаётся истинным во время выполнения алгоритма.

Для проверки палиндрома инвариант можно сформулировать так:

> Все символы за пределами диапазона `[left, right]` уже проверены и образуют
> корректные симметричные пары.

После каждой итерации диапазон уменьшается:

```text
[left, right]
```

становится:

```text
[left + 1, right - 1]
```

Если найдено несовпадение, строка сразу не является палиндромом.

Если указатели встретились или пересеклись, все необходимые пары проверены.

Для поиска суммы в отсортированном массиве инвариант другой:

> Все пары за пределами текущего диапазона уже исключены и не могут дать target.

Понимание инварианта помогает объяснять корректность алгоритма на собеседовании.

# Условия применения Two Pointers

Паттерн стоит рассмотреть, когда:

- массив или строка отсортированы
- нужно сравнивать элементы с разных концов
- нужно найти пару элементов
- нужно уменьшать диапазон поиска
- нужно изменить массив на месте
- нужно удалить дубликаты
- нужно переместить элементы
- нужно найти середину связного списка
- нужно обнаружить цикл
- требуется дополнительная память `O(1)`

# Когда Two Pointers не подходит

Паттерн нельзя применять механически ко всем задачам.

## Неотсортированный Two Sum

В обычной задаче `Two Sum` массив не отсортирован и нужно вернуть исходные
индексы.

Решение через `HashMap`:

- работает за `O(n)`
- сохраняет исходные индексы
- не требует сортировки

Если сначала отсортировать массив:

- потребуется `O(n log n)` времени
- исходные индексы могут потеряться
- понадобится хранить дополнительные пары `значение + индекс`

Поэтому для обычного `Two Sum` чаще используют `HashMap`.

Для `Two Sum II` массив уже отсортирован, поэтому Two Pointers подходит лучше.

## Нет способа отбросить варианты

Если движение указателя не позволяет гарантированно исключить часть вариантов,
паттерн может привести к неверному решению.

Перед использованием нужно понимать:

- почему можно двигать именно этот указатель
- какие варианты после движения исключаются
- почему среди исключённых вариантов нет правильного ответа

# Типичные ошибки

## 1. Неверное условие цикла

Обычно используется:

```java
while (left < right)
```

Если написать:

```java
while (left <= right)
```

центральный элемент может быть обработан повторно.

Иногда `left <= right` требуется по условию конкретной задачи, но это должно быть
осознанное решение.

## 2. Указатели не двигаются

```java
while (left < right) {
    if (values[left] == values[right]) {
        // забыли изменить left и right
    }
}
```

Это приведёт к бесконечному циклу.

Каждая ветка должна либо завершать алгоритм, либо изменять хотя бы один
указатель.

## 3. Неверный конец массива

Последний индекс:

```java
int right = values.length - 1;
```

а не:

```java
int right = values.length;
```

## 4. Потеря исходных индексов после сортировки

В задачах, где нужно вернуть индексы, сортировка меняет расположение элементов.

Нужно либо:

- не сортировать массив
- хранить исходные индексы
- выбрать другой паттерн

## 5. Сравнение символов без нормализации

В задачах со строками может потребоваться:

- привести символы к одному регистру
- пропустить пробелы
- пропустить знаки препинания
- учитывать только буквы и цифры

## 6. Неправильное движение при поиске суммы

Для отсортированного массива:

```text
sum < target → left++
sum > target → right--
```

Если двигать указатели наоборот, алгоритм будет удаляться от правильного ответа.

## 7. Ошибочная оценка сложности

Несколько вложенных циклов не всегда означают `O(n²)`.

Важно считать, сколько раз каждый указатель может пройти по структуре.

Если оба указателя суммарно проходят массив один раз, сложность остаётся `O(n)`.

# Сравнение с другими паттернами

## Two Pointers и HashMap

`HashMap` подходит, когда:

- данные не отсортированы
- нужен быстрый поиск дополнения
- нужно сохранить исходные индексы
- допустима память `O(n)`

Two Pointers подходит, когда:

- данные отсортированы
- можно двигать границы по условию
- желательно использовать `O(1)` дополнительной памяти

## Two Pointers и Sliding Window

Sliding Window обычно использует два указателя, но решает более узкий класс
задач.

В Sliding Window указатели задают непрерывный диапазон:

```text
[left ... right]
```

Окно расширяется и сужается в зависимости от условия.

Two Pointers — более общее понятие. Указатели не всегда задают окно.

## Two Pointers и Binary Search

Binary Search каждый раз делит диапазон примерно пополам.

Two Pointers обычно постепенно сдвигает левую или правую границу.

Binary Search чаще работает за:

```text
O(log n)
```

Two Pointers чаще работает за:

```text
O(n)
```

---

# Сложность

Для большинства классических задач Two Pointers:

| Операция | Сложность |
|---|---:|
| Один проход двумя указателями | `O(n)` |
| Дополнительная память | `O(1)` |
| Предварительная сортировка | `O(n log n)` |
| Два указателя после сортировки | `O(n)` |

Если массив приходится сначала сортировать, общая сложность становится:

```text
O(n log n)
```

потому что сортировка доминирует над линейным проходом.

# Краткая памятка

```text
Указатели навстречу:
left = 0
right = n - 1

while left < right:
    обработать left и right
    изменить один или оба указателя
```

```text
Поиск суммы в отсортированном массиве:

sum == target → ответ найден
sum < target  → left++
sum > target  → right--
```

```text
Slow и Fast:

slow движется на 1 шаг
fast движется на 2 шага
```

Основное правило:

> Движение каждого указателя должно быть обосновано и исключать часть
> неподходящих вариантов.
