# Hashing: HashMap и HashSet

## Основная идея

Хеширование используется для быстрого поиска данных по ключу.

В алгоритмических задачах структуры на основе хеширования позволяют:

- проверять, встречался ли элемент ранее;
- находить дубликаты;
- подсчитывать частоты;
- хранить индекс элемента;
- находить пару значений;
- группировать элементы по некоторому признаку.

Основные структуры в Java:

```java
HashSet<E>
HashMap<K, V>
```

## HashSet

`HashSet` хранит только уникальные элементы.

```java
Set<Integer> numbers = new HashSet<>();

numbers.add(10);
numbers.add(20);
numbers.add(10);
```

В множестве останутся только:

```text
10, 20
```

Метод `add()` возвращает:

- `true`, если элемент был добавлен;
- `false`, если такой элемент уже присутствовал.

```java
Set<Integer> seen = new HashSet<>();

for (int number : numbers) {
    if (!seen.add(number)) {
        return true;
    }
}
```

Такой шаблон удобно использовать для поиска повторений.

## HashMap

`HashMap` хранит пары:

```text
ключ → значение
```

Например:

```text
число → индекс
слово → количество появлений
символ → частота
ключ группировки → список элементов
```

Пример подсчета частот:

```java
Map<Integer, Integer> frequencies = new HashMap<>();

for (int number : numbers) {
    frequencies.put(
        number,
        frequencies.getOrDefault(number, 0) + 1
    );
}
```

То же самое через `merge()`:

```java
Map<Integer, Integer> frequencies = new HashMap<>();

for (int number : numbers) {
    frequencies.merge(number, 1, Integer::sum);
}
```

Для массива:

```text
[4, 2, 4, 4, 2]
```

получится:

```text
4 → 3
2 → 2
```

## HashSet или HashMap

Главный вопрос:

> Нужно ли хранить дополнительную информацию об элементе?

Если нужно только проверить наличие:

```text
HashSet
```

Если нужно сохранить значение, индекс, частоту или список:

```text
HashMap
```

| Задача | Структура |
|---|---|
| Проверка наличия элемента | `HashSet` |
| Поиск дубликата | `HashSet` |
| Подсчет частот | `HashMap<Element, Count>` |
| Хранение индекса | `HashMap<Element, Index>` |
| Группировка элементов | `HashMap<Key, List<Element>>` |

## Как работает хеширование

Упрощенно операция состоит из нескольких этапов:

1. Для ключа вычисляется `hashCode()`.
2. По результату определяется корзина — bucket.
3. Внутри корзины ключ сравнивается с существующими ключами через `equals()`.

```text
key
 ↓
hashCode()
 ↓
bucket
 ↓
equals()
```

Разные объекты могут иметь одинаковый `hashCode()`.

Это называется коллизией.

Одинаковый хеш не означает, что объекты равны. Поэтому после выбора корзины выполняется проверка через `equals()`.

## Контракт equals и hashCode

Главное правило:

```text
Если a.equals(b) == true,
то a.hashCode() должен быть равен b.hashCode().
```

Обратное утверждение неверно:

```text
Одинаковый hashCode не гарантирует равенство объектов.
```

Если собственный класс используется:

- как ключ `HashMap`;
- как элемент `HashSet`;

то необходимо корректно переопределить:

```java
equals()
hashCode()
```

## Как устроен HashSet

`HashSet` внутри использует `HashMap`.

Элемент множества хранится как ключ внутренней карты, а в качестве значения используется общий объект-заглушка.

Условно:

```text
элемент HashSet → PRESENT
```

Именно поэтому элементы в `HashSet` должны иметь корректные `equals()` и `hashCode()`.

## Сложность операций

Средняя сложность операций:

| Операция | `HashSet` | `HashMap` |
|---|---:|---:|
| Добавление | `O(1)` | `O(1)` |
| Проверка наличия | `O(1)` | `O(1)` |
| Получение значения | — | `O(1)` |
| Удаление | `O(1)` | `O(1)` |

Это ожидаемая сложность при нормальном распределении ключей по корзинам.

Если несколько ключей попадают в одну корзину, возникает коллизия и работа операции может замедлиться.

Для типичных алгоритмических задач используется оценка:

```text
один проход по массиву + HashMap/HashSet
```

Время:

```text
O(n) в среднем
```

Память:

```text
O(n)
```

## Когда применять хеширование

Признаки в условии:

- найти повторяющийся элемент;
- проверить, встречался ли элемент раньше;
- найти два числа с заданной суммой;
- подсчитать количество каждого элемента;
- сравнить частоты символов;
- сгруппировать одинаковые или эквивалентные элементы;
- найти уникальный элемент;
- обеспечить быстрый поиск без сортировки.

## Когда хеширование может не подойти

Хеширование не сохраняет естественный порядок элементов.

Если задача требует:

- отсортированный порядок;
- поиск минимального или максимального ключа;
- поиск соседнего значения;
- обработку диапазонов;

могут лучше подойти:

```java
TreeMap
TreeSet
сортировка
два указателя
бинарный поиск
```

## Шаблон: поиск дубликата

```java
public boolean containsDuplicate(int[] numbers) {
    Set<Integer> seen = new HashSet<>();

    for (int number : numbers) {
        if (!seen.add(number)) {
            return true;
        }
    }

    return false;
}
```

Сложность:

```text
Время: O(n) в среднем
Память: O(n)
```

## Шаблон: подсчет частот

```java
public Map<Integer, Integer> countFrequencies(int[] numbers) {
    Map<Integer, Integer> frequencies = new HashMap<>();

    for (int number : numbers) {
        frequencies.merge(number, 1, Integer::sum);
    }

    return frequencies;
}
```

Сложность:

```text
Время: O(n) в среднем
Память: O(k)
```

Где `k` — количество различных элементов.

В худшем случае:

```text
k = n
```

поэтому память составляет `O(n)`.

## Шаблон: поиск пары

Для каждого текущего числа можно вычислить дополнение:

```text
complement = target - current
```

Далее требуется проверить, встречалось ли нужное значение ранее.

Вариант хранения:

```text
ранее встреченное число → его индекс
```

```java
Map<Integer, Integer> indexes = new HashMap<>();

for (int i = 0; i < numbers.length; i++) {
    int complement = target - numbers[i];

    if (indexes.containsKey(complement)) {
        return new int[]{indexes.get(complement), i};
    }

    indexes.put(numbers[i], i);
}
```

Другой допустимый вариант:

```text
ожидаемое в будущем число → индекс его пары
```

```java
Map<Integer, Integer> expected = new HashMap<>();

for (int i = 0; i < numbers.length; i++) {
    if (expected.containsKey(numbers[i])) {
        return new int[]{expected.get(numbers[i]), i};
    }

    int complement = target - numbers[i];
    expected.put(complement, i);
}
```

Оба варианта имеют сложность:

```text
Время: O(n) в среднем
Память: O(n)
```

## Важность порядка действий

В задаче поиска пары сначала нужно проверить текущее число, а затем добавить его или ожидаемое дополнение в карту.

Это не позволяет использовать один и тот же индекс дважды.

Пример:

```text
numbers = [3, 3]
target = 6
```

На первой итерации сохраняется информация об индексе `0`.

На второй итерации находится пара и возвращаются индексы:

```text
[0, 1]
```

## Учебный пример

Необходимо найти первое число, которое повторно встретилось при обходе массива слева направо.

```java
public static Integer find(int[] numbers) {
    Set<Integer> seen = new HashSet<>();

    for (int number : numbers) {
        if (!seen.add(number)) {
            return number;
        }
    }

    return null;
}
```

Пример:

```text
[4, 7, 2, 7, 4] → 7
```

Сложность:

```text
Время: O(n) в среднем
Память: O(n)
```

## Типичные ошибки

### Использование HashMap, когда достаточно HashSet

Если нужно только определить наличие элемента, хранить пару ключ-значение необязательно.

### Неверная оценка памяти

```java
Set<Integer> seen = new HashSet<>();
```

Это не `O(1)` памяти.

В худшем случае множество сохранит все входные элементы:

```text
O(n)
```

### Неправильный порядок проверки и добавления

В задачах поиска пары можно случайно использовать один элемент дважды, если добавить текущее число до необходимой проверки.

### Неправильный контракт equals и hashCode

Если равные объекты имеют разные хеши, `HashMap` и `HashSet` могут работать некорректно.

### Ожидание сохранения порядка

`HashMap` и `HashSet` не предназначены для сохранения порядка вставки.

Если порядок важен, могут использоваться:

```java
LinkedHashMap
LinkedHashSet
```

## Главный вывод

Хеширование используется, когда нужен быстрый поиск элемента или связанной с ним информации.

Основной выбор:

```text
Только наличие элемента → HashSet
Элемент и дополнительные данные → HashMap
```

Типичная сложность решения с одним проходом:

```text
Время: O(n) в среднем
Память: O(n)
```
