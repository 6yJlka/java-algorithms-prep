# Sliding Window

## Что такое Sliding Window

Sliding Window — алгоритмический паттерн для обработки непрерывных участков данных:

- подмассивов
- подстрок
- непрерывных диапазонов

Основная идея состоит в том, чтобы не пересчитывать каждый участок с нуля. При движении окна алгоритм добавляет новый элемент справа, удаляет элемент, вышедший слева, и поддерживает состояние текущего окна.

Такой подход часто уменьшает сложность с `O(n × k)` или `O(n²)` до `O(n)`.

Не каждая задача на подмассив или подстроку решается Sliding Window. Для применения паттерна недостаточно только непрерывности участка.

## Когда распознавать Sliding Window

Характерные формулировки задачи:

- непрерывный подмассив
- непрерывная подстрока
- максимальная длина
- минимальная длина
- сумма непрерывного участка
- фиксированный размер `k`
- не более `k` элементов
- не менее `k` элементов
- без повторяющихся элементов
- не более `k` различных элементов

Состояние участка должно эффективно обновляться при перемещении его границ. Добавление или удаление одного элемента не должно требовать полного пересчёта окна.

Одного слова «подмассив» недостаточно для выбора паттерна. Нужно проверить, можно ли последовательно двигать границы и сохранять нужную информацию об участке.

## Границы окна

Два указателя задают границы окна:

```text
left
→ левая граница окна

right
→ правая граница окна
```

Текущее окно:

```text
[left ... right]
```

Длина окна:

```text
right - left + 1
```

Единица прибавляется потому, что обе границы входят в окно. Разность индексов показывает число переходов между ними, а не число элементов.

Пример:

```text
left = 2
right = 4

индексы:
2, 3, 4

длина:
4 - 2 + 1 = 3
```

## Состояние окна

Алгоритм обычно хранит дополнительное состояние текущего окна.

Примеры состояния:

- сумма элементов
- количество подходящих элементов
- частоты значений
- `HashSet` уникальных элементов
- `HashMap` количества вхождений
- число различных элементов
- максимальное или минимальное значение

Основная схема:

```text
добавили элемент справа
→ обновили состояние

удалили элемент слева
→ обновили состояние
```

Состояние не должно пересчитываться полностью после каждого движения окна. Именно быстрое обновление делает паттерн эффективным.

## Фиксированное окно

В фиксированном окне размер известен заранее. Сначала вычисляется состояние первых `k` элементов. Затем окно последовательно двигается вправо, новый правый элемент добавляется, а вышедший слева элемент удаляется.

Общий шаблон:

```java
int windowState = 0;

for (int i = 0; i < k; i++) {
    windowState += nums[i];
}

int answer = windowState;

for (int right = k; right < nums.length; right++) {
    windowState += nums[right];
    windowState -= nums[right - k];

    answer = Math.max(answer, windowState);
}
```

Выражение:

```java
nums[right - k]
```

обозначает элемент, который находился в предыдущем окне, но больше не входит в новое окно. После добавления `nums[right]` именно его нужно вычесть из состояния.

## Пошаговый пример фиксированного окна

Пусть даны:

```text
nums = [1, 4, 2, 10, 3, 1]
k = 3
```

Первое окно:

```text
[1, 4, 2]
сумма = 7
```

Сдвигаем окно вправо:

```text
[4, 2, 10]

7 - 1 + 10 = 16
```

Следующее окно:

```text
[2, 10, 3]

16 - 4 + 3 = 15
```

Последнее окно:

```text
[10, 3, 1]

15 - 2 + 1 = 14
```

Максимальная сумма:

```text
16
```

Каждое окно отличается от предыдущего только двумя элементами. Поэтому достаточно вычесть вышедший элемент и прибавить вошедший, а не складывать все `k` элементов заново.

## LeetCode 643 — Maximum Average Subarray I

Нужно найти максимальное среднее среди всех подмассивов размера `k`. Это прямой пример фиксированного окна.

```java
class Solution {

    public double findMaxAverage(int[] nums, int k) {
        int windowSum = 0;

        for (int i = 0; i < k; i++) {
            windowSum += nums[i];
        }

        int maxSum = windowSum;

        for (int right = k; right < nums.length; right++) {
            windowSum += nums[right];
            windowSum -= nums[right - k];

            maxSum = Math.max(maxSum, windowSum);
        }

        return (double) maxSum / k;
    }
}
```

Все окна имеют одинаковый размер `k`. Поэтому окно с максимальной суммой одновременно имеет максимальное среднее.

Среднее не нужно вычислять на каждой итерации. Достаточно сравнивать целочисленные суммы и выполнить деление один раз при возврате результата.

Сложность:

- время: `O(n)`
- дополнительная память: `O(1)`

## Динамическое окно

В динамическом окне размер заранее неизвестен. Указатель `right` расширяет окно, а `left` сжимает его.

После добавления правого элемента условие окна может нарушиться. Цикл `while` сдвигает левую границу и восстанавливает допустимость. Ответ обновляется после восстановления условия.

Общий шаблон:

```java
int left = 0;

for (int right = 0; right < data.length; right++) {
    add(data[right]);

    while (windowIsInvalid()) {
        remove(data[left]);
        left++;
    }

    updateAnswer();
}
```

Части шаблона:

- `left` хранит начало текущего окна
- цикл `for` последовательно перемещает правую границу
- `add(data[right])` добавляет новый элемент в состояние окна
- `windowIsInvalid()` проверяет нарушение условия
- `remove(data[left])` удаляет влияние левого элемента из состояния
- `left++` передвигает левую границу
- `updateAnswer()` использует уже допустимое окно

Один новый элемент может потребовать нескольких сдвигов `left`. Поэтому для восстановления условия обычно нужен `while`, а не `if`.

## Инвариант окна

Инвариант окна — условие, которое должно выполняться для текущего участка.

Примеры:

```text
размер окна равен k
в окне нет повторяющихся символов
сумма окна не превышает target
в окне не более k различных элементов
```

Основная схема:

```text
расширяем окно
→ условие может нарушиться
→ сжимаем окно
→ восстанавливаем инвариант
→ обновляем ответ
```

При поиске максимального допустимого окна ответ обычно обновляется после завершения `while`. В этот момент инвариант уже восстановлен, поэтому длина или другое состояние относятся к корректному кандидату.

## LeetCode 3 — Longest Substring Without Repeating Characters

Нужно найти длину самой длинной подстроки без повторяющихся символов. Размер окна неизвестен, поэтому используется динамическое окно и `HashSet`.

```java
class Solution {

    public int lengthOfLongestSubstring(String s) {
        Set<Character> window = new HashSet<>();

        int left = 0;
        int maxLength = 0;

        for (int right = 0; right < s.length(); right++) {
            char current = s.charAt(right);

            while (window.contains(current)) {
                window.remove(s.charAt(left));
                left++;
            }

            window.add(current);

            maxLength = Math.max(
                    maxLength,
                    right - left + 1
            );
        }

        return maxLength;
    }
}
```

Роли переменных:

```text
window
→ символы текущей подстроки

left
→ начало окна

right
→ конец окна

maxLength
→ максимальная найденная длина
```

Инвариант:

```text
в текущем окне нет повторяющихся символов
```

При появлении повтора окно сжимается слева до тех пор, пока новый символ снова не сможет войти в него без нарушения инварианта.

## Пошаговый разбор строки pwwkew

Начало обхода:

```text
p
→ длина 1

pw
→ длина 2
```

Приходит второй `w`:

```text
текущий w уже есть в окне
```

Сначала удаляется символ на позиции `left`:

```text
удаляем p
left увеличивается
```

Но старый `w` всё ещё находится в окне:

```text
удаляем старый w
left увеличивается
```

После этого добавляется новый `w`.

Дальнейшие окна:

```text
w
wk
wke
```

Максимальная длина становится равной `3`.

При следующем `w` окно сжимается до:

```text
kew
```

Ответ остаётся равным `3`.

## Почему удаляется s.charAt(left)

Правильное сжатие окна:

```java
window.remove(s.charAt(left));
left++;
```

Нельзя заменять его на:

```java
window.remove(current);
```

Окно представляет непрерывный участок, поэтому сжимать его нужно с левой стороны. `HashSet` должен содержать ровно символы подстроки:

```text
s[left ... right]
```

Если удалить только текущий символ, содержимое `HashSet` перестанет соответствовать границам окна. Кроме того, старый повторяющийся символ останется внутри непрерывного участка.

## Substring и subsequence

Разница понятий:

```text
substring
→ непрерывный участок строки
→ символы идут подряд

subsequence
→ символы можно выбирать с пропусками
```

Для строки:

```text
pwwkew
```

последовательность:

```text
pwke
```

имеет длину `4`, но не является подстрокой.

Максимальные подстроки без повторений:

```text
wke
kew
```

Их длина равна `3`.

## Почему вложенный while не означает O(n²)

Несмотря на `while` внутри `for`, сложность оценивается амортизированно:

- `right` проходит каждый элемент один раз
- `left` движется только вперёд
- каждый элемент добавляется в окно не более одного раза
- каждый элемент удаляется из окна не более одного раза

Общее число перемещений указателей:

```text
не более 2n
```

Итог:

```text
O(n)
```

а не:

```text
O(n²)
```

Для задачи с `HashSet` дополнительная память:

```text
O(min(n, размер алфавита))
```

## Sliding Window и Two Pointers

### Two Pointers

- указатели могут двигаться навстречу
- указатели могут двигаться с разной скоростью
- часто используется отсортированный массив
- состояние окна может отсутствовать
- примеры: Two Sum II, 3Sum, Valid Palindrome

```text
left →       ← right
```

### Sliding Window

- оба указателя обычно движутся слева направо
- указатели ограничивают непрерывный участок
- поддерживается состояние окна
- окно бывает фиксированным или динамическим

```text
left →
right →
```

Sliding Window можно рассматривать как отдельное применение двух указателей. Его выделяют в самостоятельный паттерн из-за работы с непрерывным окном и его состоянием.

## Когда Sliding Window неприменим

Паттерн работает не во всех задачах. Он может быть неприменим, если:

- участок не обязан быть непрерывным
- состояние нельзя корректно обновить при удалении элемента
- сдвиг `left` не гарантирует приближение к допустимому состоянию
- задача требует рассмотрения произвольных комбинаций
- условие окна не обладает подходящей монотонностью

Особенно важно ограничение задач на сумму с отрицательными числами.

Для неотрицательных чисел:

```text
расширение окна
→ сумма не уменьшается

сжатие окна
→ сумма не увеличивается
```

При отрицательных числах эта логика нарушается. Добавление элемента может уменьшить сумму, а удаление — увеличить. Поэтому простое динамическое окно может пропустить правильный участок и дать неверный результат.

## Типичные ошибки

### Пересчёт всего окна

Повторно обрабатывать все элементы каждого окна вместо обновления состояния. Это лишает паттерн преимущества по времени.

### Неправильный вышедший элемент

В фиксированном окне забывать удалить:

```java
nums[right - k]
```

### Использование if вместо while

Один сдвиг `left` может не восстановить инвариант. Сжимать окно нужно до выполнения условия.

### Удаление текущего символа

Удалять `current` вместо:

```java
s.charAt(left)
```

### Движение left без обновления состояния

Увеличивать `left`, но не удалять элемент из `HashSet` или `HashMap`. Границы и состояние окна перестанут соответствовать друг другу.

### Обновление состояния без движения left

Удалять элемент, но забывать увеличить `left`. Алгоритм останется на прежней левой границе.

### Перезапись максимума

Неправильно:

```java
maxLength = right - left + 1;
```

Правильно:

```java
maxLength = Math.max(
        maxLength,
        right - left + 1
);
```

### Обновление ответа до восстановления инварианта

Сначала нужно завершить `while`, затем использовать текущее окно как допустимое.

### Путаница substring и subsequence

Sliding Window работает с непрерывными участками. Подпоследовательность может содержать пропуски и требует другого подхода.

### Ошибочная оценка O(n²)

Вложенный `while` не означает автоматически квадратичную сложность. Нужно учитывать суммарное число движений обоих указателей.

### Лишнее деление

В задаче с одинаковым размером окон среднее не нужно считать на каждой итерации. Сравнение сумм даёт тот же порядок кандидатов.

### Автоматическое применение паттерна

Не каждая задача на подмассив решается Sliding Window. Сначала нужно проверить непрерывность, обновляемость состояния и монотонность условия.

## Краткий ответ для собеседования

Sliding Window — паттерн для эффективной обработки непрерывного участка массива или строки. Окно бывает фиксированного размера или динамически расширяется и сжимается. Указатели `left` и `right` задают его левую и правую границы. Вместо полного пересчёта алгоритм поддерживает состояние окна при добавлении и удалении элементов. В динамическом варианте после расширения сдвигается `left`, пока не восстановится инвариант. Поскольку оба указателя обычно движутся только вперёд, типичная временная сложность равна `O(n)`.
